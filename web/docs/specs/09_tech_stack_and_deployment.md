- `main` is the production branch. Auto-deploys to furnish.live via Vercel.

**Commit conventions:**
- Match the iOS app's themed-commit pattern.
- No em dashes in commit messages.
- Format: `[area]: short description`. Example: `home: build hero with sequential headline reveal`.

**Pull requests:**
- All changes go through a PR, even when working solo. PRs serve as the audit trail.
- PRs run CI (typecheck, lint, build) before merge.
- Squash merge to keep `main` history linear.

### 3.1 pnpm setup

**Install pnpm globally:**
```
npm install -g pnpm@latest
```

**Lockfile:** Commit `pnpm-lock.yaml`.

**Install command Vercel uses:** Vercel auto-detects `pnpm-lock.yaml` and runs `pnpm install`.

### 3.2 Initial install commands

For Hassan to run when scaffolding the repo:

```bash
# Initialize Next.js app
pnpm create next-app@latest furnish-web --typescript --tailwind --app --eslint --src-dir --import-alias "@/*"

cd furnish-web

# Animation
pnpm add gsap

# MDX support
pnpm add @next/mdx @mdx-js/loader @mdx-js/react remark-gfm rehype-slug rehype-autolink-headings

# Frontmatter parsing
pnpm add gray-matter reading-time

# Supabase (for waitlist only at v1)
pnpm add @supabase/supabase-js

# Icons
pnpm add lucide-react

# SEO helpers
pnpm add next-seo

# Date formatting
pnpm add date-fns

# Class management
pnpm add clsx tailwind-merge

# Dev dependencies
pnpm add -D prettier prettier-plugin-tailwindcss @types/node
```

Total expected install size: roughly 350-450 MB in `node_modules`. Acceptable.

### 3.3 Dependency philosophy

**Add only what is needed.** Do not pre-install dependencies for features that have not been built. Each new dependency is a security surface, a bundle size cost, and a maintenance burden.

**Audit dependencies before launch:**
```
pnpm audit
pnpm outdated
```

Resolve any high or critical CVEs. Update outdated packages where the change is minor or patch level.

### 3.4 Forbidden dependencies

These should not be installed without a strong reason:
- `lodash` (use native ES methods or smaller utility libraries)
- `moment` (deprecated, use `date-fns` instead)
- `jquery` (no DOM library needed)
- Any "all-in-one UI kit" like Material UI or Chakra UI (Tailwind is sufficient)

### 3.5 Bundle analysis

Add to `package.json` scripts:
```json
"analyze": "ANALYZE=true next build"
```

Run periodically to catch bundle bloat:
```
pnpm run analyze
```

## 4. Styling

### 4.1 Tailwind + CSS variables (the hybrid approach)

**Locked: Tailwind for class composition, CSS variables for tokens.**

Tailwind handles the utility classes. CSS variables (defined in `src/styles/tokens.css`) hold the brand tokens extracted from the iOS app per Document 2 §0.

`tailwind.config.ts` extends the theme to read from CSS variables:

```typescript
const config: Config = {
  content: ["./src/**/*.{ts,tsx,mdx}"],
  theme: {
    extend: {
      colors: {
        background: "var(--color-background)",
        surface: "var(--color-surface)",
        ink: "var(--color-ink)",
        accent: "var(--color-accent)",
      },
      fontFamily: {
        sans: "var(--font-sans)",
        display: "var(--font-display)",
      },
      fontSize: {
        "display-xl": "clamp(3rem, 8vw, 7.5rem)",
        "display-l": "clamp(2.5rem, 5vw, 5rem)",
        "display-m": "clamp(2rem, 4vw, 3.5rem)",
        "body-xl": "clamp(1.25rem, 1.5vw, 1.5rem)",
        "body-l": "1.125rem",
        "body-m": "1rem",
        "body-s": "0.875rem",
      },
    },
  },
  plugins: [],
};
```

This way components use Tailwind classes (`bg-background text-ink`) but the actual values come from CSS variables that match the iOS app exactly.

### 4.2 Token extraction process

When Hassan runs Claude Code on the initial build:

1. Open `app.css` (or whatever the iOS app's CSS file is named) in the existing iOS app codebase
2. Find every `:root` CSS custom property
3. Copy them all into `src/styles/tokens.css` in the marketing site
4. Add the marketing-specific additions per Document 2 §1.2 (hero gradient, editorial accent)
5. Verify the names match what `tailwind.config.ts` expects

If the iOS app token names diverge from what tailwind.config.ts expects (e.g., the app uses `--brand-primary` instead of `--color-accent`), update either the tokens or the Tailwind config so they align. The Tailwind config can be edited in this initial setup.

### 4.3 PostCSS

PostCSS is auto-configured by Next.js via `postcss.config.js`. Tailwind is included automatically. No additional plugins needed at v1.

### 5.2 Frontmatter parsing

Use `gray-matter` to parse blog post frontmatter. Helper at `src/lib/blog.ts`:

```typescript
import fs from "fs";
import path from "path";
import matter from "gray-matter";
import readingTime from "reading-time";

const BLOG_DIR = path.join(process.cwd(), "src/content/blog");

export function getBlogPosts() {
  const files = fs.readdirSync(BLOG_DIR).filter((f) => f.endsWith(".mdx"));
  return files.map((file) => {
    const slug = file.replace(/\.mdx$/, "");
    const fullPath = path.join(BLOG_DIR, file);
    const fileContents = fs.readFileSync(fullPath, "utf-8");
    const { data, content } = matter(fileContents);
    return {
      slug,
      ...data,
      readingTime: readingTime(content).text,
      content,
    };
  });
}

export function getBlogPostBySlug(slug: string) {
  const fullPath = path.join(BLOG_DIR, `${slug}.mdx`);
  const fileContents = fs.readFileSync(fullPath, "utf-8");
  const { data, content } = matter(fileContents);
  return {
    slug,
    ...data,
    readingTime: readingTime(content).text,
    content,
  };
}
```

### 5.3 FAQ JSON

FAQ data lives at `src/content/faq/questions.json` per Document 8 §8.

Loading helper at `src/lib/faq.ts`:

```typescript
import faqData from "@/content/faq/questions.json";

export function getAllFAQ() {
  return faqData.categories;

  return faqData.categories.flatMap((cat) =>
```

### 5.4 Legal pages (markdown)

Privacy Policy and Terms of Service are plain markdown at `src/content/legal/privacy.md` and `src/content/legal/terms.md`.

Render via the `react-markdown` package, OR by pre-converting to HTML at build time. Recommended approach: pre-convert with `remark` and `rehype-stringify`:

```typescript
import { remark } from "remark";
import remarkGfm from "remark-gfm";
import remarkRehype from "remark-rehype";
import rehypeStringify from "rehype-stringify";

export async function markdownToHtml(markdown: string) {
  const result = await remark()
    .use(remarkGfm)
    .use(remarkRehype)
    .use(rehypeStringify)
    .process(markdown);
  return result.toString();
}
```

This keeps the legal pages fast (no client-side rendering) and SEO-friendly.

## 6. Animation (GSAP)

### 6.1 GSAP setup

Install:
```
pnpm add gsap
```

GSAP core, ScrollTrigger, and Flip are included in the free version. CustomEase is a GSAP premium plugin (free for non-commercial use; per Doc 3 §2.3 Furnish qualifies as non-commercial at launch since the iOS app is free with no IAP). The Business Green license ($99/year) is required when Furnish becomes commercial. Until then, CustomEase is free to use under the GSAP non-commercial license. Note this in the repo README so future contributors understand the licensing trigger.

### 6.2 GSAP wrapper (lazy load)

Per Document 3 (Animation System), GSAP is heavy (~70KB gzipped including plugins) and should not block first paint. Lazy-load it. Per Doc 3 §0, the required plugin set is **ScrollTrigger + Flip + CustomEase**. Flip drives the gallery lightbox transitions (Doc 6 §5). CustomEase registers the 5 furnish-branded easing curves defined in Doc 3 §2.3 (`furnishOut`, `furnishInOut`, `furnishBack`, `furnishAnticipate`, `furnishQuick`).

**Architecture:** Per Doc 3 §17, all motion code lives in `src/lib/motion/` (a directory, not a single file). The GSAP loader is one file in that directory: `src/lib/motion/gsap-loader.ts`. The directory contains 16+ files at full build (one per motion moment, plus eases, durations, hooks, reduced motion, public API index). Doc 9 only specifies the loader file. Doc 3 §17 is authoritative for the full directory layout.

`src/lib/motion/gsap-loader.ts`:

```typescript
"use client";

let gsapInstance: typeof import("gsap").gsap | null = null;
let registered = false;

export async function getGsap() {
  if (gsapInstance && registered) return gsapInstance;

  const gsapModule = await import("gsap");
  const { ScrollTrigger } = await import("gsap/ScrollTrigger");
  const { Flip } = await import("gsap/Flip");
  const { CustomEase } = await import("gsap/CustomEase");

  gsapModule.gsap.registerPlugin(ScrollTrigger, Flip, CustomEase);

  // Register the 5 furnish-branded easing curves once (per Doc 3 §2.3)
  if (!registered) {
    CustomEase.create("furnishOut", "0.22, 1, 0.36, 1");
    CustomEase.create("furnishInOut", "0.65, 0, 0.35, 1");
    CustomEase.create("furnishBack", "0.34, 1.56, 0.64, 1");
    CustomEase.create("furnishAnticipate", "0.7, -0.4, 0.4, 1.4");
    CustomEase.create("furnishQuick", "0.4, 0, 0.2, 1");
    registered = true;
  }

  gsapInstance = gsapModule.gsap;
  return gsapInstance;
}
```

The `useReducedMotion()` hook lives in a separate file `src/lib/motion/reduced-motion.ts` per Doc 3 §17 (not bundled with the GSAP loader). Components import both from the public API at `@/lib/motion` (the index.ts barrel file), never from the internal files directly.

Components that use motion call `getGsap()` inside `useEffect`, ensuring it loads after first paint. The custom ease names (`furnishOut`, `furnishBack`, etc.) are then available in any GSAP timeline string: `gsap.to(el, { ease: "furnishOut", duration: 0.6 })`.

### 6.3 Reusable motion patterns

Document 3 (Animation System) defines several motion moments. Each becomes a reusable hook or component:

- `useScrollReveal()`: triggers an element to fade and slide in when it enters the viewport
- `useStaggeredReveal()`: same but for groups of elements (used in galleries, value props)
- `useHeroSequence()`: the sequential headline reveal pattern
- `<CompareSlider />`: the before/after slider component

These live in `src/components/motion/`.

### 6.4 Reduced motion compliance

Every motion hook checks `prefers-reduced-motion`. If set, the animation is skipped and the element is shown in its final state immediately.

## 8. Email capture (waitlist)

### 8.1 Storage at v1: Supabase

Per Hassan's Q4 = C. Use the existing Supabase backend that powers the iOS app. Store waitlist emails in a new table.

**Table schema (run as SQL in Supabase):**

```sql
CREATE TABLE waitlist (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email text NOT NULL UNIQUE,
  source text DEFAULT 'home_page',
  utm_source text,
  utm_medium text,
  utm_campaign text,
  user_agent text,
  ip_address text,
  created_at timestamptz DEFAULT now()
);

CREATE INDEX idx_waitlist_created_at ON waitlist (created_at DESC);
CREATE INDEX idx_waitlist_email ON waitlist (email);

ALTER TABLE waitlist ENABLE ROW LEVEL SECURITY;

-- Only service-role can read/write waitlist
CREATE POLICY waitlist_no_public_access ON waitlist FOR ALL USING (false);
```

**Why service-role only:** the Vercel API endpoint uses the service-role key (server-side, never exposed to the client) to insert rows. No public read access. No way for someone to scrape emails.

### 8.2 API endpoint

**Path:** `/api/waitlist` (POST)

**File:** `src/app/api/waitlist/route.ts`

```typescript
import { NextResponse } from "next/server";
import { createClient } from "@supabase/supabase-js";

const supabaseAdmin = createClient(
  process.env.SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!
);

export async function POST(req: Request) {
  try {
    const { email, source } = await req.json();

    // Validate email
    if (!email || !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
      return NextResponse.json({ error: "Invalid email" }, { status: 400 });
    }

    // Insert (idempotent via unique constraint)
    const { error } = await supabaseAdmin
      .from("waitlist")
      .insert({
        email: email.toLowerCase().trim(),
        source: source || "home_page",
        user_agent: req.headers.get("user-agent") || null,
      });

    if (error && error.code !== "23505") {
      // 23505 = unique violation (already on list, that is fine)
      console.error("Waitlist insert error:", error);
      return NextResponse.json({ error: "Server error" }, { status: 500 });
    }

    return NextResponse.json({ ok: true });
  } catch (err) {
    return NextResponse.json({ error: "Server error" }, { status: 500 });
  }
}
```

```typescript
export default function sitemap(): MetadataRoute.Sitemap {
  const baseUrl = "https://furnish.live";
```

## 15. Security

### 15.1 Headers

Set via `next.config.mjs` per §12.4:
- X-Frame-Options: DENY (prevents clickjacking)
- X-Content-Type-Options: nosniff
- Referrer-Policy: strict-origin-when-cross-origin
- Permissions-Policy: camera, microphone, geolocation off (this is a marketing site, not the app)

### 15.2 Service role key handling

The Supabase service-role key is the master key for the database. It must NEVER:
- Be prefixed with `NEXT_PUBLIC_`
- Appear in client-side code
- Be committed to git
- Be logged

It exists only in Vercel environment variables and is used only in server-side API routes.

### 15.3 Input validation

All user input (waitlist email, anything else) is validated server-side before being written to the database. Per §8.2, the email is regex-validated and lowercased before insertion.

### 15.4 Dependency security

Run `pnpm audit` before each deploy. Update high or critical CVEs immediately.
